# System Model

## Overview

The project used a simulated microgrid to investigate reinforcement-learning-based frequency regulation under changing operating conditions and stochastic disturbances.

The microgrid model was implemented in MATLAB/Simulink and provided the physical system environment in which the PPO controller was trained and evaluated.

The available project information confirms the presence of conventional generation, battery energy storage, an inverter, load demand, and frequency regulation dynamics. Some detailed component parameters and topology from the original model are no longer available.

---

## Microgrid Components

The documented system included:

- Conventional generation
- Battery energy storage
- Battery inverter
- Inverter control block
- Electrical load
- Microgrid frequency dynamics

Renewable-generation variations were also considered as part of the changing operating conditions used in the project. The exact renewable-generation technology and its representation in the original Simulink model are not currently available.

## Battery Energy Storage

The battery energy storage system served as the controllable resource for frequency regulation.
The PPO agent generated a continuous control signal that was passed to an inverter control block associated with the battery inverter.
The agent therefore operated above the lower-level inverter control mechanism.
The RL controller did not directly perform inverter switching.

## Inverter Control

The inverter control block received the continuous signal generated by the PPO agent and translated the supervisory control command into the corresponding inverter behaviour.
The exact lower-level inverter control algorithm and its parameters are not available from the surviving project records.
For the historical reconstruction, the inverter control block should therefore be treated as an interface between the learning-based supervisory controller and the physical battery-inverter dynamics.

## Load Model

Load demand was varied using stochastic time-series disturbances.
The purpose was to expose the controller to changing operating conditions rather than a single fixed operating point.

The project considered:
- different load levels;
- stochastic load variations;
- different disturbance magnitudes;
- disturbance profiles different from those used during training.

The exact statistical generation procedure, numerical load ranges, and time-series parameters are unavailable.

## Frequency Dynamics

Frequency deviation was a primary measure of system behaviour and one of the principal observations provided to the RL controller.
The controller's objective was to reduce deviations from the nominal operating frequency following changes in load and other system conditions.
The project therefore treated frequency response as a central indicator of controller performance.
The exact nominal frequency, generator parameters, inertia constants, damping coefficients, and other physical model parameters are not available in the surviving records.

## Interaction With the RL Environment

The Simulink model served as the physical environment for the reinforcement learning process.
At each decision step:
```text
1. Microgrid evolves
        ↓
2. System measurements are obtained
        ↓
3. RL state is constructed
        ↓
4. PPO selects a continuous action
        ↓
5. Action is passed to inverter control block
        ↓
6. Battery inverter responds
        ↓
7. Microgrid frequency changes
        ↓
8. New state and reward are returned
```
The exact simulation step size and agent decision interval are not currently known.

## State-Related Measurements

The refined RL state incorporated information from the system and controller:
State

```text
├── Frequency deviation
├── Previous control action
└── Inverter output
```
These variables were selected to provide the agent with information about both the current frequency condition and the recent system/control response.
The reformulation was motivated by the observation that the initial state representation was not capturing enough of the system dynamics for consistent control decisions.

## Disturbances and Operating Conditions

The controller was evaluated under varying conditions rather than a single fixed scenario.
- The evaluation varied:
- load level;
- disturbance magnitude;
- stochastic disturbance profile.

The training and evaluation profiles were distinct, allowing the learned policy to be assessed under disturbance sequences that were not identical to those used during training.

## Model Fidelity and Historical Limitations

The original MATLAB/Simulink model is not currently available.
Consequently, the following details cannot be claimed as recovered historical values:

These details should be established independently if the system is reimplemented.

## Reimplementation Strategy

A future implementation should reproduce the functional behaviour of the original system while documenting all newly selected parameters.
The reimplementation should separate the physical model from the RL controller:
```text
reimplementation/
├── models/
│   └── microgrid/
├── environment/
│   └── frequency_regulation/
├── agent/
│   └── ppo/
├── training/
└── evaluation/
```
This separation will make it possible to test different control formulations without coupling the RL algorithm to the underlying microgrid model.

## Summary

The system model provided a simulated environment for investigating adaptive frequency regulation using reinforcement learning.
The key relationship was:
```text
Changing system conditions
          ↓
     Microgrid dynamics
          ↓
    Frequency response
          ↓
      RL state
          ↓
       PPO agent
          ↓
 Continuous control signal
          ↓
 Inverter control block
          ↓
     Battery inverter
          ↓
    Microgrid response
```
The system was designed to examine whether a learning-based controller could maintain more consistent frequency regulation when operating conditions and disturbances changed.
